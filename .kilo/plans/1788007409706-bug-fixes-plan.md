# Bug Fixes Implementation Plan

## Overview
Implementation plan for the high/medium priority bugs identified in the Chismisa codebase review.

---

## Priority 1: Critical Security & Architecture Fixes

### 1.1 Distributed Rate Limiter (High)
**File**: `src/lib/rate-limit.ts` → Replace with Upstash Redis

**Changes**:
- Add `@upstash/ratelimit` and `@upstash/redis` dependencies
- Create new `src/lib/rate-limit-redis.ts` with sliding window using Upstash
- Keep in-memory fallback for local dev (when `UPSTASH_REDIS_URL` not set)
- Update imports in `src/app/api/messages/route.ts` and `src/app/api/groups/route.ts`

**Validation**: Deploy to Vercel preview, verify rate limiting works across multiple instances.

---

### 1.2 Admin Page Auth Guard (High)
**File**: `src/app/chismis-admin/page.tsx`

**Changes**:
- Convert to async server component
- Check for `ADMIN_SECRET` in cookies/headers
- Redirect to `/login` or return 403 if missing/invalid
- Reuse `verifyAdminSecret` from `src/lib/actions/admin.ts`

**Validation**: Access `/chismis-admin` without secret → 403; with secret → panel loads.

---

### 1.3 Enforce SESSION_SECRET in All Environments (High)
**File**: `src/lib/session-secret.ts`

**Changes**:
- Remove dev fallback entirely
- Throw if `SESSION_SECRET` not set (all environments)
- Update `.env.example` with required variable

**Validation**: Start dev server without `SESSION_SECRET` → clear error message.

---

### 1.4 Fix Auto-Registration Race Condition (High)
**File**: `src/lib/actions/auth.ts` (lines 34-64)

**Changes**:
- Wrap user creation + session in a Prisma transaction
- Or: check existence, hash, then create with `create` (unique constraint handles race)
- Remove the `P2002` catch block — let unique constraint enforce, then re-query

**Validation**: Simulate concurrent registration requests (e.g., with `wrk` or parallel fetches).

---

### 1.5 Enforce Min 8-Char Password on Login Too (High)
**File**: `src/lib/actions/auth.ts` (line 28)

**Changes**:
- Change `password.length < 4` to `password.length < 8`
- Add migration note: existing users with short passwords will need reset
- Consider adding `passwordStrength` field to User model for future migration

**Validation**: Try login with 4-char password → rejected.

---

## Priority 2: Data Consistency & UX Fixes

### 2.1 Fix Reaction Rollback Refetch (Medium)
**File**: `src/lib/hooks/use-chat.ts` (lines 537-560)

**Changes**:
- On reaction failure, fetch only the affected message: `/api/messages?groupId=...&since=...&limit=1`
- Or: merge server state only for the specific message ID
- Keep other optimistic updates intact

**Validation**: Simulate reaction failure (network error) → only that message reverts.

---

### 2.2 Fix Optimistic Message Replacement Race (Medium)
**File**: `src/lib/hooks/use-chat.ts` (lines 476-490)

**Changes**:
- Track optimistic message IDs in a `Set` ref
- When poll returns data, filter out any message whose ID is in the optimistic set
- Then merge confirmed message by replacing the optimistic one
- Simplify: use `Message` type with `isOptimistic` flag instead of temp IDs

**Validation**: Send message, artificially delay action resolution, verify no duplicates.

---

### 2.3 Coordinate Polling Across Tabs (Medium)
**File**: `src/lib/hooks/use-chat.ts` (polling effect, line 210)

**Changes**:
- Use `BroadcastChannel("chismisa-poll")` to coordinate
- Only one tab polls; others listen for `new-messages` events
- On tab close, elect new poller
- Fallback to per-tab polling if `BroadcastChannel` unavailable

**Validation**: Open 3 tabs, verify only 1 makes `/api/messages` requests.

---

### 2.4 Fix Pusher Channel Reuse Bug (Medium)
**File**: `src/lib/realtime.ts` (lines 94-137, 166-184)

**Changes**:
- Single subscription owner per channel
- `subscribeToGroup` should not unbind if channel is badge-watched
- Refactor: `ensureChannel(groupId)` returns channel, callers bind their own handlers
- `unsubscribeFromGroup` only unsubscribes if no other owners

**Validation**: Switch groups rapidly, verify no duplicate `new-message` handlers fire.

---

### 2.5 Add Capacitor Plugin Check Before Haptics (Medium)
**File**: `src/components/message-bubble.tsx` (lines 129-130, 193-194)

**Changes**:
- Import `Capacitor` from `@capacitor/core`
- Check `Capacitor.isPluginAvailable('Haptics')` before calling
- Log warning in dev if unavailable

**Validation**: Test on web (no Capacitor) → no errors in console.

---
